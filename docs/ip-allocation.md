# VPN 출구 IP 배정 (ipalloc)

자체 운영하는 영상 서비스의 사용자를 N 명씩 묶어, 한 묶음이 항상 같은 출구 IP 로
나가게 만든다. 사용자는 WireGuard 설정 파일 하나만 받으면 된다.

```bash
python3 -m ipalloc plan --users 1000 --per-ip 20      # 얼마나 필요한지
python3 -m ipalloc assign --users users.csv --endpoints endpoints.csv --out out/
python3 -m ipalloc wg --assignments out/assignments.csv --out out/wg/
sh out/wg/genkeys.sh                                   # 키 생성 (wireguard-tools 필요)
```

---

## 1. 규모 산정

기준: 사용자 1,000명 · 출구 IP 하나를 20명이 공유 · 1인당 월 20분 시청.

```
$ python3 -m ipalloc plan --users 1000 --per-ip 20

사용자 1,000명을 20명씩 묶으면 출구 IP 50개가 필요하다.
터널 대역 10.77.0.0/16 는 묶음 256개 / 묶음당 253명까지 수용한다.
```

| 항목 | 값 |
|---|---|
| 출구 IP | 50개 |
| 묶음 | 50개 (묶음당 20명) |
| IP 1개의 월 전송량 | 15 GB |
| 전체 월 전송량 | 750 GB |
| IP 1개의 최악 대역 (20명 동시) | 100 Mbps |

**용량은 병목이 아니다.** 월 20분 부하는 IP 하나당 평균 동시접속 0.009명이다.
20명이 전원 동시에 붙어도 1080p 기준 100 Mbps 면 되고, 이는 가장 싼 VPS 회선도
감당한다. 이 프로젝트에서 돈이 드는 것은 대역폭이 아니라 **IPv4 주소 개수**다.

단, 이 계산에는 조건이 붙는다 → [4. 전체 터널 vs 분할 터널](#4-전체-터널-vs-분할-터널).

### 가정을 바꿔서 보기

```bash
# 4K 로 올리고, 접속이 하루(월의 3%)에 몰리고, 회선이 100 Mbps 인 경우
python3 -m ipalloc plan --users 1000 --per-ip 20 --mbps 16 --peak 0.03 --link-mbps 100
```

`--peak` 은 한 달 전체 시간 중 접속이 몰리는 구간의 비율이다. 기본값 0.10 은
"평일 저녁에 몰린다" 정도의 가정이다. **"이번 달 영상 오늘까지 보세요" 같은 공지를
보내는 운영이라면 이 숫자는 무의미해진다** — 그때는 최악 수치(전원 동시)가 그대로
현실이 되므로, 판정도 최악 기준으로 한다.

## 2. 입력 파일

### users.csv — 명부

`user_id` 컬럼 하나만 있으면 된다. `id` / `name` 같은 컬럼명도 받고, 엑셀이 붙이는
BOM 도 처리한다.

```csv
user_id,label
u0001,1기-홍
u0002,1기-김
```

`user_id` 는 파일명과 설정 파일에 그대로 들어간다. 영숫자·점·밑줄·하이픈만 쓸 수 있다.
`label` 은 사람이 알아보기 위한 것이므로 **개인정보를 넣지 않는 편이 좋다** — 배정표
CSV 와 WireGuard 설정 주석에 그대로 남는다.

테스트용 명부가 필요하면:

```bash
python3 -m ipalloc sample-users --count 1000 --out users.csv
```

### endpoints.csv — 출구 IP 목록

```csv
ip,region,provider,listen_host,listen_port,note
203.0.113.1,sg,acme,vpn01.example.com,51820,
203.0.113.2,sg,acme,,51820,
```

`ip` 만 필수다. `listen_host` 를 비우면 `ip` 를 쓴다. 입구(사용자가 접속하는 주소)와
출구(서비스에서 보이는 주소)가 다른 구성이면 `listen_host` 에 입구를 적는다.

연속 대역을 받았다면 CSV 없이 바로 쓸 수 있다:

```bash
python3 -m ipalloc assign --users users.csv --cidr 203.0.113.0/26 --out out/
```

> `/26` 은 64개가 아니라 **62개**다. 네트워크 주소와 브로드캐스트 주소는 빠진다.
> 이걸 64로 세고 용량을 잡으면 마지막 묶음이 갈 곳을 잃는다.

## 3. 배정

```bash
python3 -m ipalloc assign \
    --users users.csv --endpoints endpoints.csv \
    --per-ip 20 --out out/
```

출력은 두 개다.

| 파일 | 내용 |
|---|---|
| `out/assignments.csv` | 사용자 한 명당 한 줄 — 묶음, 출구 IP, 터널 주소 |
| `out/groups.csv` | 묶음 한 개당 한 줄 — 인원, 빈자리, 서브넷 |

### 사람이 바뀔 때는 반드시 `--existing` 을 준다

이 도구의 핵심 규칙은 **이미 배정된 사람은 움직이지 않는다** 이다. 매달 명부만 바꿔
처음부터 다시 돌리면, 아무 상관 없는 사용자의 출구 IP 가 바뀌고 설정 파일을 전부
다시 배포해야 한다.

```bash
python3 -m ipalloc assign \
    --users users_2월.csv --endpoints endpoints.csv \
    --existing out/assignments.csv \
    --per-ip 20 --out out_2월/
```

```
사용자 1000명 · 묶음 50개 (묶음당 최대 20명) · 유지 999 · 신규 1 · 이탈 1 · 미배정 0
  명부에서 빠진 사용자 1명의 자리를 비웠다: u0005
  이 사람들의 설정은 서버에서 [Peer] 블록을 지워야 실제로 차단된다.
```

- 빠진 사람의 자리는 비고, 그 자리를 신규가 채운다.
- 기존 사용자는 묶음·출구 IP·터널 주소가 모두 그대로다.
- 풀의 순서를 바꾸거나 IP 를 추가해도 기존 묶음 ID 는 자기 출구 IP 에 붙어 있다.
- 예외는 하나뿐이다 — **쓰던 출구 IP 가 풀에서 사라지면** 그 묶음 사람들만 재배정된다.

> **주의**: 배정표에서 사람을 빼는 것만으로는 접속이 막히지 않는다. 서버의
> `[Peer]` 블록이 남아 있으면 그대로 붙는다. 이탈자가 생기면 설정을 다시 내보내
> 서버에 반영해야 한다.

### 검증

배정표는 손으로 고치게 되어 있다. 고친 뒤에는 검사한다.

```bash
python3 -m ipalloc verify --assignments out/assignments.csv --per-ip 20
```

중복 배정, 정원 초과, 한 IP 를 두 묶음이 쓰는 경우, 터널 주소가 서브넷을 벗어난
경우를 잡는다. `wg` 명령도 내보내기 전에 같은 검사를 돌리고, 실패하면 파일을
쓰지 않는다.

## 4. 전체 터널 vs 분할 터널

**이 문서에서 가장 중요한 선택이다.**

```bash
# 전체 터널 (기본값) — 사용자의 모든 트래픽이 출구 IP 로 나간다
python3 -m ipalloc wg --assignments out/assignments.csv --out out/wg/

# 분할 터널 — 서비스 대역으로 가는 트래픽만 터널을 탄다
python3 -m ipalloc wg --assignments out/assignments.csv --out out/wg/ \
    --allowed-ips 198.51.100.0/24
```

| | 전체 터널 (`0.0.0.0/0`) | 분할 터널 (서비스 대역) |
|---|---|---|
| IP 통일 | 확실 | 서비스 대역에 한해 확실 |
| 월 전송량 | **추정 불가** | 15 GB/IP 그대로 |
| 사용자 체감 | VPN 켠 동안 전부 느려짐 | 영향 없음 |
| 사용자가 VPN 끄고 접속 | 막지 못함 | 막지 못함 |

1번 장의 750 GB 는 **사용자가 영상만 볼 때**의 값이다. 전체 터널에서 사용자가 VPN 을
켜둔 채 하루를 보내면 그 사람의 모든 트래픽이 회선을 지나간다. 서비스 IP 대역이
고정이라면 분할 터널을 쓰는 편이 비용·성능 양쪽에서 낫다.

어느 쪽이든 **사용자가 VPN 을 끄고 접속하는 것은 막지 못한다.** IP 통일을 실제로
강제하려면 서비스 쪽에서 허용 IP 목록(= `groups.csv` 의 `egress_ip` 50개) 외의
접속을 거부해야 한다. 클라이언트 설정만으로는 강제되지 않는다.

## 5. 서버 구성

### 키 생성

내보낸 설정에는 개인키가 없다. 자리표시자만 있고, 채우는 것은 `genkeys.sh` 다.

```bash
cd out/wg && sh genkeys.sh
```

`wireguard-tools`(`wg` 명령)가 필요하다. 이미 만들어진 키는 재사용하므로 두 번 돌려도
기존 사용자의 설정이 무효가 되지 않는다.

> `out/wg/keys/` 에는 **모든 사용자의 개인키**가 들어간다. 저장소에 올리지 말 것.
> (`.gitignore` 에 등록되어 있다.)

### 한 호스트에 여러 출구 IP

50개 IP 를 한 호스트에 붙이는 구성이라면, 보조 IP 를 인터페이스에 올리고 묶음마다
WireGuard 인터페이스를 띄운다.

```bash
# 보조 IP 를 올린다 (클라우드 콘솔에서 인스턴스에 할당한 뒤)
ip addr add 203.0.113.2/24 dev eth0

# 묶음별 인터페이스
cp out/wg/server/g001.conf /etc/wireguard/
wg-quick up g001
```

설정의 핵심은 `PostUp` 의 SNAT 한 줄이다.

```
PostUp = iptables -t nat -A POSTROUTING -s 10.77.0.0/24 -o eth0 -j SNAT --to-source 203.0.113.1
```

**이 규칙이 없으면 모든 묶음이 호스트의 기본 IP 로 나가고 배정표는 아무 의미가 없다.**
인터페이스 이름이 `eth0` 가 아니면 `--wan ens5` 처럼 지정한다.

IP 포워딩도 켜야 한다:

```bash
sysctl -w net.ipv4.ip_forward=1
```

### 설정 배포

`out/wg/clients/<묶음>/<사용자>.conf` 파일 하나가 그 사용자의 전부다. 모바일이면
QR 코드가 편하다:

```bash
qrencode -t ansiutf8 < out/wg/clients/g001/u0001.conf
```

**이 파일에는 개인키가 들어 있다.** 이메일 첨부나 단체 채팅방 업로드는 피하고,
1회용 링크나 대면 전달을 쓸 것.

## 6. IP 를 어디서 가져오는가

### 레지덴셜은 이 구조에 쓸 수 없다

먼저 구조 문제다. 레지덴셜/ISP 프록시는 **HTTP/SOCKS5 엔드포인트**로 판다. 그 호스트를
내가 소유한 게 아니므로 두 가지가 불가능하다.

- 거기에 WireGuard 서버를 띄울 수 없다.
- 사용자가 그 IP 로 **인바운드 접속**을 할 수 없다.

5장의 구조는 `사용자 → (내 호스트의 공인 IP) → SNAT → 서비스` 다. 프록시는 방향이
반대라, 굳이 쓰려면 이렇게 된다.

```
사용자 → WireGuard 서버(데이터센터 IP 가 여전히 필요) → 레지덴셜 프록시 → 서비스
```

**대체가 아니라 추가다.** 데이터센터 호스트 비용은 그대로 나가고, 그 위에 레지덴셜
비용이 얹히며, 홉이 하나 늘어 지연과 장애 지점이 함께 늘어난다.

### 과금 단위가 반대다

데이터센터는 **IP 개수**로, 로테이팅 레지덴셜은 대부분 **트래픽 GB** 로 과금한다.
어느 쪽이 유리한지는 그 서비스의 IP 대 트래픽 비율이 정한다.

이 프로젝트는 IP 50개에 월 750 GB 다 — IP 는 적고 트래픽은 그 몇 배다. 즉 IP 로
과금되는 쪽이 유리한 모양이다. `cost` 명령이 손익분기 GB 단가를 계산한다.

```bash
python3 -m ipalloc cost --users 1000 --per-ip 20 \
    --dc-ip-monthly 3.6 --dc-hosts 2 --dc-host-monthly 20 --dc-egress-per-gb 0.09 \
    --res-per-gb 2.0
```

```
[판정]
  레지덴셜: 데이터센터 대비 월 1,252.50 초과 (5.4배).
  손익분기 GB 단가: 0.3300
  이보다 싼 종량 단가를 받아야 레지덴셜이 유리하다. 현재 넣은 단가는 2.0000 다.
```

> 위 단가는 **형식을 보이기 위한 예시**다. 공급사·국가·시점에 따라 달라지므로
> 직접 받은 견적을 넣어야 의미가 있다. 손익분기 값 자체는 견적과 무관하게
> 워크로드에서 나온다 — 그 아래 단가를 받을 수 있는지만 확인하면 된다.

트래픽이 늘수록 손익분기 단가는 내려간다. 즉 **화질을 올리거나 전체 터널을 쓰면
레지덴셜은 더 불리해진다.**

### static ISP 프록시 (IP 월정액형)

로테이션이 없는 대신 IP 당 월정액을 받는 제품도 있다. `--res-ip-monthly` 로 계산한다.
IP 월정액이 데이터센터보다 높으면 **GB 단가가 0이어도 이길 수 없는 구조**가 되고,
`cost` 가 그렇게 보고한다.

### 그래서 어디서 가져오는가

| 조달처 | 형태 | 메모 |
|---|---|---|
| 클라우드 보조 IP | 인스턴스에 IPv4 추가 할당 | 가장 단순. **타입별 ENI 당 IP 한도를 먼저 확인할 것** |
| VPS 추가 IP | 저가 VPS 의 추가 IP 옵션 | IP 당 단가가 가장 싸고 전송량이 포함된 경우가 많다 |
| 여러 사업자 분산 | 호스트 5~10대에 IP 분산 | 한 대가 죽어도 일부만 중단된다 |
| BYOIP / 대역 임대 | 자체 /24 확보 후 광고 | 50개 규모에는 과하다. 수백 개 이상일 때 검토 |

`ipalloc` 은 조달처를 가리지 않는다. `endpoints.csv` 에 IP 목록만 넣으면 되고,
`provider` / `region` 컬럼으로 분산 현황을 관리할 수 있다.

### 비용을 줄이는 유일한 축

```
월 비용 = 호스트 수 x 인스턴스 단가 + IP 수 x 추가 IPv4 단가 + 750 GB x 전송량 단가
```

비중은 대개 **추가 IPv4 단가가 지배적**이다. 750 GB 는 웬만한 VPS 의 기본 제공량
안에 들어가고, 인스턴스는 부하가 거의 없어 가장 작은 것으로 충분하다. 그래서
비용을 줄이려면 IP 개수를 줄이는 것 — `--per-ip` 를 올리는 것 — 외에 방법이 없다.

`--per-ip 40` 으로 올리면 IP 는 25개로 줄고 최악 대역은 200 Mbps 로 는다. 여전히
회선은 병목이 아니므로, **IP 당 인원은 용량이 아니라 아래의 장애 반경으로 결정해야
한다.**

## 7. 먼저 알아야 할 것

용량 말고 실제로 문제가 되는 것들이다.

**1. 장애 반경이 20명 단위로 묶인다.**
한 사용자가 서비스에서 차단당하면 같은 IP 를 쓰는 20명이 함께 차단된다. 로그상
구분이 되지 않기 때문이다. `--per-ip` 를 올려 IP 비용을 아끼면 이 반경도 같이
커진다. 이것이 IP 당 인원을 정하는 실제 기준이다.

**2. 인스턴스당 붙일 수 있는 보조 IP 수에 한도가 있다.**
클라우드는 인스턴스 타입별로 ENI 당 IP 개수를 제한한다. 50개를 한 대에 붙이는
구성이 불가능할 수 있으니, IP 를 확보하기 전에 **인스턴스 타입별 한도를 먼저
확인할 것.** 여러 호스트에 나누면 한 대가 죽었을 때의 반경은 줄지만, IP 를 다른
호스트로 옮기는 절차가 필요해진다.

**3. 한 달에 한 번 쓰는 VPN 은 운영 부담이 크다.**
사용자는 한 달 전에 넣은 설정을 잊고, 기기를 바꾸고, 앱을 지운다. 접속이 드물수록
"설정이 안 돼요" 문의 비율이 높아진다. 1,000명 규모면 재발급 절차를 사람 손으로
감당하기 어렵다 — 재발급을 셀프서비스로 만들 계획을 처음부터 세울 것.

**4. 싼 국가일수록 지연이 크다.**
출구를 먼 국가로 잡으면 RTT 가 커지고 영상 시작 지연과 탐색 반응이 느려진다.
전체 터널이면 그 사용자의 웹 브라우징 전체가 같이 느려진다. 요금 차이가 체감
품질 저하를 감당할 만한지 먼저 확인할 것.

**5. MTU.**
기본값 1420 은 대부분의 환경에서 안전하지만, 일부 모바일 회선에서는 더 낮춰야
한다(1380 등). "연결은 되는데 영상만 안 나온다"는 증상이면 MTU 를 의심할 것.

**6. 클라이언트 설정만으로는 IP 통일이 강제되지 않는다.**
VPN 을 끄고 접속하면 그만이다. 4번 장의 허용 IP 목록을 서비스 쪽에 적용해야
실제로 강제된다.

## 명령 요약

| 명령 | 용도 |
|---|---|
| `plan --users N --per-ip K` | 필요한 IP 개수와 용량 산정 (파일 불필요) |
| `capacity --users N --per-ip K` | 용량만 |
| `cost --users N --dc-ip-monthly P ...` | 데이터센터 vs 레지덴셜 월 비용과 손익분기 GB 단가 |
| `sample-users --count N --out F` | 테스트용 명부 생성 |
| `assign --users F --endpoints F --out D` | 배정표 생성 |
| `assign ... --existing F` | 증분 배정 (기존 사용자 고정) |
| `verify --assignments F` | 배정표 불변식 검사 |
| `wg --assignments F --out D` | WireGuard 설정 내보내기 |

공통 옵션: `--per-ip`(기본 20), `--tunnel-cidr`(기본 `10.77.0.0/16`),
`--minutes`(기본 20), `--mbps`(기본 5.0), `--peak`(기본 0.10),
`--link-mbps`(기본 1000), `--quota-gb`.
