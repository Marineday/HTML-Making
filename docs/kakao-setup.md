# 카카오 오픈채팅 연결 절차

> ## ⚠️ 시작 전에
>
> 카카오톡에는 오픈채팅방에 외부 메시지를 보내는 **공식 API가 없다.**
> 이 문서의 방법은 안드로이드 알림 접근 권한을 이용한 **비공식 자동화**이며,
> 카카오 운영정책 위반으로 **계정이 영구정지될 수 있다.**
> 방장 계정이 정지되면 오픈채팅방도 함께 잃는다.
>
> 텔레그램/디스코드로 먼저 코어를 검증하고, 위험을 감수하겠다고 판단한 경우에만 진행하라.

## 필요한 것

- 24시간 켜둘 수 있는 안드로이드 기기 (또는 에뮬레이터)
- 그 기기에서 접근 가능한 서버 (같은 공유기 안이면 사설 IP로 충분)
- 메신저봇R (Messenger Bot R) 앱

## 전체 그림

```
run.py loop ──POST /enqueue──> 브리지 큐 서버 <──GET /pull── 메신저봇R
   (PC/서버)                     (PC/서버)      ──POST /ack─>  (안드로이드)
                                                                   │ bot.send()
                                                                   ▼
                                                          카카오 오픈채팅방
```

**왜 pull 인가**: 안드로이드 기기는 공인 IP가 없고 배터리 최적화 때문에 인바운드
연결을 유지하지 못한다. 그래서 서버가 밀어넣는 대신 기기가 당겨 간다.

**왜 lease/ack 인가**: "pull 하면 삭제" 방식은 응답이 도중에 끊기면 메시지가 조용히
사라진다(모바일 회선에서 드물지 않다). 여기서는 pull 시 임대만 걸고, 카톡 전송에
성공한 뒤 ack 를 받아야 삭제한다. 임대가 만료되면 다시 대기 상태로 돌아간다.

## 1. 브리지 토큰 생성

```bash
python3 -c 'import secrets; print(secrets.token_urlsafe(32))'
```

출력값을 저장한다. 16자 미만이면 서버가 기동을 거부한다.

```bash
export BRIDGE_TOKEN="여기에_생성한_토큰"
```

## 2. 브리지 서버 실행

```bash
python3 run.py bridge --port 8080 --db bridge.db
```

확인:

```bash
curl http://127.0.0.1:8080/health
# {"ok": true, "pending": 0, "delivered": 0}
```

서버가 실행 중인 기기의 **사설 IP**를 확인해 둔다 (`ip addr` / `ifconfig`).
예: `192.168.0.10`

> 인터넷에 노출한다면 반드시 HTTPS 리버스 프록시(caddy, nginx) 뒤에 둘 것.
> 토큰이 평문으로 흐른다.

## 3. config.json 에 카카오 어댑터 켜기

```json
{
  "type": "kakao_bridge",
  "enabled": true,
  "bridge_url": "http://127.0.0.1:8080",
  "room": "오픈채팅방_정확한_이름",
  "token": "${BRIDGE_TOKEN}",
  "batch_size": 3
}
```

`room` 은 카카오톡에 표시되는 **방 이름과 정확히 일치**해야 한다. 공백·이모지까지
그대로. 방 이름을 바꾸면 봇이 멈춘다.

`batch_size` 는 한 메시지에 묶을 딜 수다. 짧은 메시지를 연달아 쏘면 도배로 판정되니
1보다 크게 두는 편이 안전하다.

## 4. 안드로이드 준비

1. 메신저봇R 설치
2. **알림 접근 권한** 허용 (설정 → 앱 → 특별한 접근 → 알림 접근)
3. **배터리 최적화 예외** 지정 — 이걸 안 하면 몇 시간 뒤 조용히 죽는다
4. 가능하면 기기를 상시 충전 상태로 두고 화면을 켜둔다

## 5. 스크립트 설치

메신저봇R 에서 새 스크립트를 만들고 `messengerbot/hotdeal.js` 내용을 붙여넣은 뒤,
상단 설정 3개를 고친다.

```js
const BRIDGE_URL   = "http://192.168.0.10:8080";   // 브리지 서버 주소
const BRIDGE_TOKEN = "2단계에서_생성한_토큰";
const TARGET_ROOM  = "오픈채팅방_정확한_이름";       // config.json 의 room 과 동일해야 함
```

컴파일(저장)하면 폴링이 시작된다.

## 6. ★ 방 세션 확보 ★

**가장 흔한 실패 원인이다.**

메신저봇R 은 그 방에서 메시지를 **한 번 수신한 뒤에야** 전송 세션을 확보한다.
스크립트를 켜자마자 보내려 하면 실패한다.

→ 대상 오픈채팅방에서 아무 메시지나 하나 오면 자동으로 풀린다.
직접 방에 아무 말이나 한 번 쳐도 된다.

세션이 없으면 스크립트가 `bot.send 가 false 반환` 로그를 남기고 **ack 하지 않는다.**
메시지는 큐에 남아 있으므로 세션이 잡히는 즉시 다음 폴링에서 나간다.

## 7. 동작 확인

방에서 `!핫딜상태` 를 치면 봇이 응답한다.

```
핫딜봇: 폴링 중 / 주기 60초
```

수동 테스트:

```bash
# 큐에 직접 하나 넣어보기
curl -X POST http://127.0.0.1:8080/enqueue \
  -H "X-Bot-Token: $BRIDGE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"room":"오픈채팅방_정확한_이름","text":"테스트 메시지"}'
```

1분 안에 방에 뜨면 성공이다.

## 문제 해결

| 증상 | 원인 / 조치 |
|---|---|
| 방에 아무것도 안 옴, `/health` 의 `pending` 이 계속 증가 | 안드로이드가 폴링을 못 하고 있다. `BRIDGE_URL` 이 기기에서 실제로 접근 가능한 주소인지 확인 (`127.0.0.1` 은 기기 자신을 가리키므로 안 된다) |
| `bot.send 가 false 반환` 로그 | 방 세션 없음 → 6단계 참고. 방에서 메시지 하나 받으면 풀린다 |
| `사용 가능한 전송 API 를 찾지 못했습니다` | 메신저봇R 버전 문제. 앱을 최신으로 업데이트 |
| 401 응답 | `BRIDGE_TOKEN` 이 서버와 스크립트에서 다르다 |
| 처음엔 되다가 몇 시간 뒤 멈춤 | 배터리 최적화가 앱을 죽였다. 4단계의 예외 지정 확인 |
| 같은 메시지가 두 번 옴 | ack 요청이 유실된 경우. 설계상 최소 1회 전달이므로 드물게 발생할 수 있다 |
| `대기열이 가득 찼습니다` | 기기가 오래 죽어 있었다. 기기를 살리고, 필요하면 `bridge.db` 를 지워 큐를 비운다 |
| 방 이름을 바꾼 뒤 멈춤 | `config.json` 의 `room` 과 스크립트의 `TARGET_ROOM` 을 새 이름으로 함께 수정 |

## 위험을 줄이는 운영 습관

- `max_sends_per_run` 을 5 이하로 유지한다
- `batch_size` 를 2~3으로 두어 메시지 통수를 줄인다
- `POLL_INTERVAL_MS` 를 60초 미만으로 낮추지 않는다
- 방장 계정이 아닌 **부계정**으로 봇을 돌린다 — 정지되어도 방을 잃지 않는다
- 방 공지에 자동 봇이 돌고 있음을 명시한다
