# 구독 만료 관리 사이트 + 만료 전 문자 자동 안내 (`renew.py`)

운영자가 웹에서 고객(이름·번호·만료일)을 관리하면, 매일 도는 작업이
**만료 N일 전 고객에게 문자를 보낸다.** 고객은 사이트에 들어오지 않고 문자만 받는다.

```
[관리 사이트]  고객 등록 / 엑셀 붙여넣기 / +1개월 연장 / 오늘 안내 미리보기 / 발송 기록
      │ SQLite (renewal.db)
      ▼
[크론 매일 10:05] renew.py remind ─┬─ 10시 전 → 종료
                                   ├─ 대상 > max_per_run → 아무것도 안 보내고 멈춤 (사고 방지)
                                   └─ 대상에게 솔라피 문자 → 기록
```

| 화면 | 기능 |
|---|---|
| 고객 | 이용 중 / 7일 내 만료 / 만료됨 / 오늘 문자 대상 요약, 검색, D-day 표시, **+1개월** 버튼, 수정·삭제 |
| 문자 안내 | 오늘 보낼 안내 미리보기(실제 문구), **지금 발송** 버튼, 발송 기록, "불명" 건 재발송 허용 |
| 일괄 등록 | 엑셀에서 표를 복사해 붙여넣기 (탭·쉼표 모두 가능). 같은 번호는 만료일 갱신 |

---

## 빠른 시작

```bash
cp renew.example.json renew.json               # .gitignore 됨
export RENEW_ADMIN_PASSWORD='12자-이상-비밀번호'
python3 renew.py serve                          # http://127.0.0.1:8090
```

1. 브라우저에서 로그인 → **일괄 등록**에 고객 명단 붙여넣기
2. **문자 안내** 화면에서 오늘 나갈 문구를 확인한다
3. `python3 renew.py remind --dry-run` 으로 크론이 보낼 대상을 확인한다
4. `renew.json` 의 `sms.provider` 를 `solapi` 로 바꾸고 명단에 **본인 번호로 시험**한다
5. 크론 등록:

```cron
5 10 * * *  cd /path/to/repo && python3 renew.py remind >> logs/renew.log 2>&1
```

## 안내 규칙

- `reminder_days: [7, 1]` → 만료 **7일 전**과 **1일 전**에 한 번씩 보낸다. `0` 을 넣으면 만료 당일에도 보낸다.
- **창이 여러 개 열려 있으면 가장 가까운 것 하나만 보낸다.** 만료 하루 전에 등록한 고객에게는 D-1 만 가고, D-7 은 "건너뜀"으로 기록된다.
- **같은 안내는 두 번 나가지 않는다.** 기록의 키가 (고객, 만료일, 며칠 전)이다.
- **연장하면 새 주기가 된다.** 만료일이 바뀌면 새 만료일 기준으로 다시 D-7, D-1 안내가 나간다.
  **+1개월** 버튼은 아직 만료 전이면 기존 만료일부터, 이미 만료됐으면 오늘부터 연장한다. 1월 31일 +1개월은 2월 28일(윤년 29일)이다.
- **서버가 하루 꺼져 있었어도** 창이 열려 있는 동안(예: D-7~D-2) 다음 실행에서 따라잡는다.
- `이용 중` 을 끄거나 `문자 수신 거부` 를 켠 고객에게는 보내지 않는다.

## 사고 방지 장치

| 장치 | 막는 사고 |
|---|---|
| `max_per_run` (기본 50) — 넘으면 **아무것도 보내지 않고** 멈춤 | 만료일을 일괄로 잘못 넣어 전원에게 문자가 나가는 것 |
| `send_hour` (기본 10시) | 크론 설정 실수로 새벽에 문자가 나가는 것 |
| 타임아웃·5xx → "불명", 자동 재시도 안 함 | 같은 고객에게 두 통이 나가는 것 |
| 발송 버튼 잠금 | 버튼 연타로 두 번 발송되는 것 |
| 일괄 등록은 전부 성공하거나 전부 취소 | 명단 일부만 들어가 무엇이 빠졌는지 모르게 되는 것 |
| `auto_send: false` | 사람이 **문자 안내** 화면에서 확인하고 버튼을 눌러야만 나감 |

한도에 걸리면 사이트의 **문자 안내** 화면에서 대상을 확인하고, "한도 초과를 확인했고 그래도 보냅니다"를 체크해서 보낸다.
명령줄에서는 `renew.py remind --force` 를 쓴다.

## 보안

- 비밀번호는 12자 이상, 환경변수로 넣는다. 같은 IP 에서 5번 틀리면 15분 동안 잠긴다.
- 세션 쿠키는 서명돼 있고(HttpOnly, SameSite=Strict) 12시간 뒤 만료된다. `admin.secret_key` 를 비워두면 재시작할 때 모두 로그아웃된다.
- 모든 변경 요청에 CSRF 토큰을 검사하고, 모든 출력은 HTML 이스케이프한다.
- **기본은 `127.0.0.1` 에서만 접속된다.** 밖에서 쓰려면 HTTPS 리버스 프록시 뒤에 둔다:

```caddy
# Caddyfile — 도메인만 있으면 HTTPS 인증서를 자동 발급한다
admin.example.com {
    reverse_proxy 127.0.0.1:8090
    header_up X-Forwarded-Proto https
}
```

  리버스 프록시 없이 `0.0.0.0` 으로 열면 비밀번호가 평문으로 오간다.
- 로그인 제한은 접속 IP 기준이다. 프록시 뒤에서는 모든 요청이 `127.0.0.1` 로 보이므로, 누가 5번 틀리면 **운영자도 15분 동안 잠긴다.** 필요하면 프록시에서 접속 IP 를 제한한다.

## 법·운영 (⚠️ 법률 자문 아님, 정보 정리)

- **개인정보보호법**: 고객 전화번호를 영업 목적으로 수집·보관하려면 수집·이용 동의를 받고, 보관 기간과 파기 기준을 정해야 한다. 이용이 끝난 고객은 삭제한다(삭제하면 발송 기록도 함께 지워진다).
- **정보통신망법**: 만료 안내는 **정보성 문자**다. 할인이나 재가입 이벤트 같은 광고성 문구를 넣으면 `(광고)` 표기, 수신거부 방법 안내, 야간(21~08시) 발송 제한이 적용된다.
- **발신번호 사전등록**이 필요하다 ([solapi.md](solapi.md)).
- 서버 한 대에서 SQLite 하나를 쓴다. **`renewal.db` 를 매일 백업할 것** (예: `sqlite3 renewal.db ".backup backup/renewal-$(date +%F).db"`).

## 명령어

| 명령 | 설명 |
|---|---|
| `renew.py serve [--host] [--port]` | 관리 사이트 |
| `renew.py remind` | 오늘 안내 발송 (크론용) |
| `renew.py remind --dry-run` | 대상과 문구만 출력 |
| `renew.py remind --force` | 한도 초과·`auto_send=false` 여도 발송 |
| `renew.py list` | 고객 목록과 D-day |

## 검증 상태

| 구성요소 | 상태 |
|---|---|
| 안내 창 계산, 건너뜀, 연장 주기, 한도, 재시도, 불명 처리 | ✅ 단위 테스트 |
| 로그인·잠금·세션 위조·만료, CSRF, XSS 이스케이프 | ✅ 실제 소켓 종단 테스트 |
| 일괄 등록(탭/쉼표, 전부 아니면 전무, 같은 번호 갱신), 연장, 발송 버튼 | ✅ 실제 소켓 종단 테스트 |
| 데스크톱·모바일(390px) 화면 | ✅ 브라우저 스크린샷 확인, 가로 스크롤 없음 |
| 솔라피 실제 발송 | ⚠️ 미검증 — familyinvite 와 같은 발송 코드. 본인 번호로 시험 필요 |
