# 단가 기반 딜 평가

"신라면 12,900원"은 싼지 알 수 없다. **20개입이면 개당 645원**이고, 최근 30일
중앙값이 개당 910원이었다면 **29% 저렴한 초특가**다. 이 판단을 자동으로 한다.

```
🔥 농심 신라면 20개입 12,900원
📍 토스핫딜
💰 12,900원
📊 🔥🔥🔥 초특가 · 645원/개 · 30일 중앙값 910원 대비 29%↓ · 역대 최저 · 표본 6건
🔗 토스 앱 → 홈 → 핫딜 에서 확인
```

## 동작

```
제목 ──▶ 수량 파싱 ──▶ 단가 계산 ──▶ 상품 식별 ──▶ 과거 단가 조회 ──▶ 등급
        "20개입"     645원/개      {신라면,농심}    중앙값 910원      초특가
```

### 1. 수량 파싱 (`hotdeal/pricing.py`)

| 표기 | 결과 |
|---|---|
| `20개입`, `12병`, `100매`, `60정`, `30포`, `30롤` | 개수 |
| `500ml`, `1.5L`, `2리터` | 용량 (ml 로 환산) |
| `500g`, `2kg` | 무게 (g 으로 환산) |
| `190ml*30캔` | 30개 + 5,700ml (곱셈 표기와 단위를 **이중 계산하지 않음**) |
| `2L x 12병` | 12개 + 24,000ml |

가격(`12,900원`)·할인율(`30%`)·시각(`8시`)은 수량으로 읽지 않는다.

**기준 우선순위: 개수 > 용량 > 무게.** 같은 상품이라도 어떤 글은 "20개입",
어떤 글은 "2.4kg"으로 쓴다. 기준이 섞이면 비교가 무의미하므로 기록할 때
기준도 함께 저장하고 **같은 기준끼리만 비교한다.**

### 2. 상품 식별

제목을 토큰으로 쪼개고 **부분집합 관계**로 같은 상품을 판정한다.

```
"[G마켓] 농심 신라면 20개입 (12,900원/무료)"  →  {신라면, 농심}
"[쿠팡] 신라면 10개입 7,900원"                →  {신라면}
                                    {신라면} ⊆ {신라면, 농심}  →  같은 상품
```

제거되는 것: **쇼핑몰 이름**(쿠팡·G마켓·11번가…), 홍보 문구(특가·최저가·무료배송…),
수량 토큰(20개입·500ml…). 쇼핑몰 이름을 안 지우면 몰마다 다른 상품으로 갈려
비교 표본이 영원히 쌓이지 않는다.

`신라면` vs `신라면블랙`은 토큰이 달라 **다른 상품**으로 본다.

### 3. 등급

| 등급 | 조건 (기본값) | 표시 |
|---|---|---|
| 초특가 | 중앙값의 70% 이하 | 🔥🔥🔥 |
| 특가 | 85% 이하 | 🔥 |
| 평균 이하 | 100% 이하 | 🙂 |
| 평범 | 그 이상 | 😐 |
| 비교 데이터 부족 | 표본 < `min_samples` | 🆕 |
| 단가 불명 | 수량을 못 읽음 | (표시 없음) |

## 설계상 지키는 것

**평균이 아니라 중앙값을 쓴다.** 제목 파싱은 원리상 반드시 일부 틀린다.
오파싱 한 건("신라면 2,000,000원")이 평균은 통째로 망가뜨리지만 중앙값은
거의 흔들리지 않는다.

**표본이 적으면 등급을 매기지 않는다.** `min_samples`(기본 5) 미만이면
"비교 데이터 부족"이라고 말하고 끝낸다. 틀린 단가로 "초특가"를 외치는 것이
봇의 신뢰를 가장 빨리 죽인다. 3 미만으로는 설정할 수 없다.

**확신이 없으면 침묵한다.** 수량을 못 읽으면 등급을 붙이지 않고 딜만 보낸다.

**가격 이력은 필터와 무관하게 전부 쌓는다.** 토스 딜만 기록해서는
"평소보다 싸다"를 판단할 기준이 생기지 않는다. 수집한 모든 딜을 기록한다.

**자기 자신은 기준에서 제외한다.** 방금 들어온 딜이 자기 중앙값에 섞이지 않는다.

## 설정

```json
"pricing": {
  "enabled": true,
  "db_path": "prices.db",
  "window_days": 30,
  "min_samples": 5,
  "super_deal_ratio": 0.70,
  "good_deal_ratio": 0.85,
  "below_average_ratio": 1.00,
  "retention_days": 180
}
```

등급으로 발송을 거르려면:

```json
"filters": {
  "min_grade": "특가",        // "" / "평균이하" / "특가" / "초특가"
  "allow_ungraded": true      // 단가 불명·표본 부족 딜을 통과시킬지
}
```

`allow_ungraded: false` 로 두면 처음 보는 상품은 절대 안 나간다.
초기에는 이력이 없으므로 방이 통째로 조용해진다.

## 운영

**첫 2~4주는 `min_grade` 를 비워두고 이력을 쌓아라.** 표본이 없으면 등급을
매길 수 없고, 등급으로 거르면 아무것도 안 나간다.

이력이 쌓였는지 확인:

```bash
sqlite3 prices.db "SELECT COUNT(*) FROM price_history;"
sqlite3 prices.db "SELECT product_key, COUNT(*) c, ROUND(AVG(unit_price)) FROM price_history GROUP BY product_key ORDER BY c DESC LIMIT 20;"
```

오판이 보이면:

| 증상 | 조치 |
|---|---|
| 다른 상품이 같은 상품으로 묶임 | `pricing.py` 의 `_NOISE_WORDS` 에서 과하게 지우는 단어를 뺀다 |
| 같은 상품이 안 묶임 | `_NOISE_WORDS` 에 쇼핑몰·홍보 단어를 추가한다 |
| 단가가 이상함 | `parse_quantity()` 결과를 확인. 새 단위 표기면 `_COUNT_UNITS` 에 추가 |
| 초특가가 너무 자주 뜸 | `super_deal_ratio` 를 낮춘다 (0.70 → 0.60) |
| 초특가가 아예 안 뜸 | `min_samples` 를 확인. 이력이 부족한 것일 수 있다 |
